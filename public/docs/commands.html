WhatsApp command guide

Send these commands in the WhatsApp Protection bot chat. Unpaired numbers may use only /pair. After their own WhatsApp account is successfully linked, they can use the other commands. The configured owner account is always authorized.

Commands

  • /pair — create a genuine WhatsApp device-linking code for the number sending the command. Use it in a private chat; the code is returned in that same chat.
  • /menu — open the branded interactive menu.
  • /developers — show developer contacts with WhatsApp contact buttons.
  • /activate ban_protection — enable outbound reply serialization, rate limits and queue caps.
  • /activate bug_protection — enable detailed runtime error capture and bounded reconnect recovery diagnostics.
  • /activate soam_protection — enable suspicious command monitoring, command-abuse detection and temporary sender cooldowns.

What the protections do

Ban Protection: When enabled, bot responses are serialized per recipient, spaced by at least 1.8 seconds, limited to 8 sends per recipient per minute and capped at 20 queued sends. This is a risk-reduction control, not a ban-prevention guarantee.

Bug Protection: When enabled, runtime and connection failures are recorded as security events. Reconnection uses exponential backoff with jitter and a bounded retry delay.

SOAM Protection: When enabled, command attempts are monitored. Eight command attempts in 60 seconds or five repeats of the same command trigger a five-minute sender cooldown. SOAM also logs inbound bursts at 40 messages per sender per minute and repeated identical text patterns at 15 repeats per minute, storing a short content hash rather than the message body. Unauthorized command attempts are logged; commands are available only to the configured owner or a number with an active linked-device record, whether SOAM is enabled or not.

WhatsApp Protection cannot inspect WhatsApp's internal enforcement systems, reverse account restrictions, or guarantee that an account cannot be banned or compromised.
