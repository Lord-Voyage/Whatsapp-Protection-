TRUST CENTRE

Security overview

Implemented controls and their boundaries

WhatsApp Protection provides risk-reduction controls around its own bot process. It does not control WhatsApp or Meta infrastructure and cannot guarantee that an account will not be restricted, compromised or abused.

Session security

  • Baileys authentication files are stored under DATA_DIR/auth on the persistent service disk.
  • Session files and SQLite data are not served by the public website.
  • The public dashboard exposes only coarse service health; it cannot view private activity logs or change settings.
  • Protection settings are changed through owner-only WhatsApp commands.
  • Back up session data securely and never commit it to source control.

Command security

  • Bot commands are restricted to OWNER_NUMBER, or the linked account number when that variable is unset.
  • Pairing requests are rate limited.
  • SOAM monitoring records unauthorized command attempts, command bursts, repeated commands and temporary cooldowns.
  • Security events are stored in SQLite and are not exposed by the public dashboard.

Outbound anti-spam controls

When Ban Protection is enabled, automated bot replies are serialized per recipient, spaced by at least 1.8 seconds, limited to eight sends per recipient per minute and capped at 20 queued sends. These controls apply to messages sent by this bot process; they do not inspect all activity on the linked WhatsApp account.

Runtime recovery

Reconnect attempts use exponential backoff with jitter and a bounded delay. When Bug Protection is enabled, runtime errors and connection failures are also recorded as security events for dashboard review.

Malware and account monitoring boundaries

This release does not scan uploaded files, inspect the phone for malware, detect WhatsApp's internal account-enforcement signals, or verify all linked-device activity. Do not treat SOAM monitoring as a substitute for device security or WhatsApp's own security settings.

Report a vulnerability

For a security report, contact the developers listed on the Contact page. Do not send session files, pairing codes, passwords or private message contents.
